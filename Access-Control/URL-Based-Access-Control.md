# URL-Based Access Control Can Be Circumvented

**Platform:** PortSwigger Web Security Academy  
**Category:** Access Control / Front-End Routing Misconfigurations  
**Difficulty:** Apprentice  
**Tool:** Burp Suite Community Edition  
**Status:** Solved  

## 1. Objective
Bypass front-end access restrictions using non-standard HTTP headers like `X-Original-URL`.

## 2. Vulnerability Overview
Web architectures often place a reverse proxy or web application firewall (WAF) in front of the application server to restrict access to sensitive paths (like `/admin`). If the back-end application trusts custom routing headers (such as `X-Original-URL` or `X-Rewrite-URL`) sent by the front-end, an attacker can request a permitted path while supplying a restricted path in the header to trick the backend into routing them to the admin panel.

## 3. Testing Methodology
1. **Identify Front-End Restriction:** Attempt to access `/admin` directly and observe a 403 Forbidden response generated by the front-end proxy.
2. **Test Routing Headers:** Send a request to a benign endpoint (e.g., `/`) using Burp Suite Repeater and add the header `X-Original-URL: /admin`.
3. **Analyze Response:** Observe if the back-end application interprets the header and serves the administrative interface.
4. **Perform Admin Task:** Adapt the technique to execute administrative actions (e.g., deleting a user) through the header injection.

## 4. Remediation
- Ensure front-end proxies and back-end servers maintain consistent parsing rules and authorization logic.
- Disable trust in arbitrary routing headers unless strictly necessary and properly secured.
